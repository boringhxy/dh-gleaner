# 质量与安全

## 质量校验的目标

抓取结果必须**像一份文章清单**，而不是导航页、广告页、数据库推荐页、平台宣传页或错误页面。

## `suspect` 与 `failed` 的判定条件

判定**逐刊进行**，再把最差的结论汇到整批：13 本里 12 本抓崩、1 本正常，聚合看仍
是「有文章、标题干净」，但那批结果不能覆盖上一次完整的待筛清单。

出现下列任一情况即标记为 `suspect`，并且**不覆盖**旧的 `review.md` / `pending.json`：

- 单期抓取把期次解析成 `0年第0期`。
- 标题里导航、广告、平台推荐类文本占比过高（词表见 `dhgleaner/textutil.py` 的 `NAVIGATION_*`，`capture` 闸门与各解析器共用一份）。
- 标题或摘要里出现解码替换符 U+FFFD，说明站点编码被判读错，整批文本不可信。
- 标题重复比例异常。
- 手动 URL 页面缺少配置要求的期刊名、IssueID 或栏目关键词。
- Airiti 等平台返回页面的标题、期刊名、IssueID 与目标不一致。
- 批量抓取中部分期刊失败 / 异常，但仍有其他刊出了结果。
- 栏目分页触到 `maxChannelPages` 上限，清单可能只覆盖前若干页。

下列情况标记为 `failed`（同样不覆盖旧清单）：

- 整批没有任何期刊进入抓取。
- 全部期刊都失败，或全部只给出合法的空结果（已处理过 / 关键词筛完无命中）。
- 单刊完全没捕获到文章。

## 抓取节流

站点是公共资源，工具默认克制：

- 重试按 `retryInterval` **指数退避**，单次最长 300 秒；站点给了 `Retry-After` 就听站点的。
- `401/403/412` 属于「明确拒绝自动化」，**一次都不重试**，直接报失败并提示改用 `--url` 或转人工。
- 同一主机的逐页/逐期请求之间按 `harvestDelay` 限速。
- 栏目分页数有 `maxChannelPages` 硬上限——「共 N 页」是从页面文本正则抠的，抠错就是上万个请求。

## 旧清单保护

- 成功抓取覆盖前，必须自动备份旧的 `data/pending.json` 与 `data/review.md`。
- 失败或 `suspect` 时只写 `data/last_capture_status.json`。
- 终端输出必须明确说明当前 `review.md` 是否仍是旧内容。

这条保护同样适用于导入：当导入在预检阶段中止（无可导入文章 / Zotero 连不上 / Collection 缺失）时，`pending.json`、`review.md` 与 `import_report.md` **都不写**。失败不该留下痕迹。

## 退出码

`capture` / `capture-channel` / `harvest` 用退出码把质量结论交给调用方，脚本不必去解析终端文本：

| 码 | 常量 | 对应质量 |
|----|------|----------|
| 0 | `EXIT_OK` | `success` |
| 1 | `EXIT_FAILED` | `failed`（参数错误同样是 1） |
| 2 | — | argparse 的参数错误，由 argparse 自己占用 |
| 3 | `EXIT_SUSPECT` | `suspect`：抓到了但闸门不信，或只有部分刊成功 |

`2` 留给 argparse，所以 `suspect` 用 `3`——把「我命令写错了」和「站点没给数据」混在同一个码里，脚本就没法分别处理。

## PDF 安全降级

- 捕获阶段不下载 PDF。
- 导入阶段下载 PDF 前，先确认期刊配置允许自动下载。
- 下载后校验文件类型与大小。
- 下载失败、非 PDF、文件过小、被验证码拦截，或 Zotero 配额不足时，**不能导致元数据导入失败**。
- 降级信息写入 Zotero 的 Extra 字段，并可添加 `PDF待手动下载` 标签。

## 隐私与密钥

- `config.local.json` 保存 Zotero `webLibraryId` 与 `webApiKey`，不得公开。
- 文档、日志与终端摘要不得输出完整 API Key。
- 仓库与文档只展示配置模板，不展示真实用户 ID 与 Key。
- 工具只读取你的凭据，不发放、不代管、不上传。

## 合规边界

- 不绕过验证码、登录或付费权限。
- 不批量下载未授权全文。
- 不把 PDF 下载失败伪装成成功。
- 不自动创建 Zotero Collection（默认），避免条目落进错误目录。

## 可操作的失败信息

失败信息应当包含：

- 失败的期刊与目标（期次 / 栏目 / URL）。
- 失败所处的阶段：定位、下载页面、解析、质量校验、Zotero 导入，还是 PDF 挂载。
- 旧筛选清单是否被保留。
- 下一步建议，例如改用 `--url`、检查 Collection、转人工校正流程。

MCP 通道下这些信息以 `failureKind` 与 `suggestedAction` 的形式返回，便于客户端决定下一步，详见 [mcp.md](mcp.md)。
